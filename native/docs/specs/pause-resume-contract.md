# 文件边界暂停与续转合同

native 引擎与 App 的协议 1 对接约定。两端分别实现；完整产品验收由整合后运行结果决定。

## CLI 与事件

- 默认转换行为不变。只有 `--checkpoint-dir PATH` 启用检查点；`--pause-file PATH` 是合作暂停令牌，`--resume` 要求验证并复用已有检查点。后两个参数必须同时提供 checkpoint-dir；首次转换不能复用非空检查点目录，resume 不能隐式创建新任务。
- 暂停令牌存在时，在源文件边界停止提交新工作；已开始的文件完成本地内容持久化，工作线程收束后返回。首次扫描输入身份时仍可取消；恢复阶段先完成只读验证，再接管检查点并处理取消令牌，验证失败保留原检查点。暂停最迟在扫描结束及当前文件完成后生效。
- 真正暂停退出 **75**。JSON Lines 最后使用 `type=result`，`report.status="paused"`，包含绝对 `checkpointDir`、`filesCompleted`。只使用已有 progress/log/result 事件类型。普通完成仍为 complete/退出 0；失败与取消非 0，不能返回 paused 或 complete。
- `filesCompleted` 是已持久化本地内容的唯一“规范源路径 + 累积矩阵”工作项数；纯索引文件也算一个。同源不同矩阵分别计数，父文件的本地内容可完成而其引用子树尚未完成。它不是 GLB 数，也不是全部子树已完成数。
- progress 的 convert.done 在恢复时从已持久化数量开始，后续只增加新完成的工作项。paused 报告另带 `filesReused`（本次使用已持久化内容的工作项数）；complete 检查点报告同样给出复用证据。普通无检查点的成功报告字段和默认值保持现状。
- `--capabilities` 增加 `pauseResume:true`；协议仍为 1，默认 meshopt、threads=2、预算不限、原编码透传。

## 绑定、持久化与恢复

- 输入身份覆盖当前根入口集合、全部可达源文件、正式 OSG 读取过程实际打开的外部图片/对象与 metadata.xml，使用内容 SHA-256，不凭路径、长度或修改时间命中缓存。源文件和外部引用即使位于输入目录以外也纳入身份。输入或引用解析变化必须拒绝复用。
- 有效 SRS、数值化 origin、几何/纹理策略、请求线程数、内存预算、输出路径及转换器版本、二进制、已加载且有磁盘文件的运行库/插件身份一并绑定；分发模式另外校验运行时清单列出的文件。checkpoint-dir 与暂停/取消令牌位置不是编码参数。修改任一绑定项必须显式失败，不能退回整任务重跑。
- 检查点保存每个文件实例的本地内容、边界盒、引用路径及累积矩阵、审计记录；子树完成后再保存瓦片清单。恢复跳过已持久化内容的编码，包括其子树尚未完成的父文件；仍按原引用顺序组合子树和审计结果。
- 每个记录有 SHA-256 校验和与任务身份绑定，总账保存完整记录集合和摘要，删除无资产的纯索引记录同样必须失败；记录列出的 GLB、原图与瓦片清单均保存内容摘要。恢复前验证全部记录、资产和工作目录清单；缺失、改写、额外资产、符号链接或不完整记录均拒绝。不同任务的旧缓存不能混入。
- 检查点只能由一个进程持有，使用随进程释放的系统文件锁。正常暂停退出后可在新进程恢复。原子写入保证完整记录切换；强杀/断电留下的未提交资产或坏记录会被拒绝，不承诺断电持久性或自动修复损坏检查点。
- 扫描和转换期间输入应保持不变；写文件前后及暂停/发布前复核源内容。发生变化则失败清理当前已接管任务，不能发布混合产物。文件内容的 SHA-256 是完整性检查，不是对恶意篡改者的签名认证。

## 事务与停止语义

- 私有资产在 checkpoint-dir/work 下。暂停时保留检查点，移除尚未发布的顶层报告/入口，不移动到输出目录。成功时整体发布输出并移除检查点。
- checkpoint-dir 与输出路径必须互不包含，工作目录不能包含源文件，暂停令牌放在两者之外。跨文件系统发布先复制到输出同级独立暂存，再原子重命名；复制阶段仍响应取消/暂停。
- `--cancel-file`、SIGINT/SIGTERM 继续代表真正取消，优先于暂停；取消不能冒充暂停。接管并验证检查点后，正常失败和取消清理本任务工作区。验证失败不修改原检查点，便于修正参数或检查原因。
- 已有非空输出始终拒绝覆盖，开始和发布边界都检查。暂停/续转不改变引用闭包、失败传播、同源矩阵实例、线程/预算调度、原图和几何保真规则。

## App

- App 增加 queued/running/pausing/paused 等状态及 POST `/api/jobs/{id}/pause`、`/resume`；原 cancel 保留。暂停请求建立暂停令牌，不取消进程上下文。`Result.Paused` 明确传给任务管理器。
- 没有开始的排队任务可直接暂停，恢复时正常转换；已实际转换的任务才附加 --resume。检查点路径由持久化任务拥有，重启保留暂停历史，不自动运行。恢复前移除旧暂停令牌；保留令牌会再次暂停。
- native 未声明 pauseResume 时，App 不展示或接受暂停/续转。只有退出 75 与最终 paused 报告一致才记为暂停，只有退出 0、complete 报告与已发布入口一致才记为完成。

## 验收

用程序生成并经正式 OSG 序列化的小型真实 fixture，不依赖历史故障样本：

1. 文件处理中触发暂停，退出 75、最后 result/paused，无对外入口；新进程恢复后，所有 GLB、纹理和 tiles JSON 与一次完整转换逐文件一致。报告中耗时、RSS、复用计数属运行数据，单独比较业务审计记录。
2. 检查已完成内容没有重新写入；覆盖父内容已完成但子引用未完成、多层引用、同源不同矩阵、原编码图片、meshopt/raw、多个根和预算门控。
3. 输入内容变化（包括同长度同 mtime）、外部资源变化、参数变化、转换器身份变化、坏记录/资产、额外资产均失败且无发布。
4. 真正取消清理、暂停保留；两令牌同时存在取消优先；已存在非空输出不覆盖。
5. 原有 50 项转换与 13 项纹理回归保持通过。主代理统一整合 App、引用修复和发布校验后再验收真实模型，不在子任务全量转换模型。
