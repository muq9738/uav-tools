# App 暂停与续转实现规格

共同协议以 [native 暂停合同](../../native/docs/specs/pause-resume-contract.md) 为准。本规格限定 App 任务管理、子进程协议、HTTP 和现有 Web 界面；不修改 native 或打包流程。App 的进程协议测试使用真实子进程 stub，真实 native 与模型验收由整合阶段完成。

## 状态与操作

- `queued → running → succeeded / failed / canceled` 保持原义。
- native 能力 `pauseResume:true` 才启用暂停和续转；缺少该能力仍可执行普通转换，暂停/续转接口返回 501，界面不显示操作。
- 排队任务 `queued → paused`：移出队列，不创建检查点、不启动进程；继续时 `paused → queued`，首次启动不传 `--resume`。
- 运行任务 `running → pausing`：持久化暂停请求，建立本任务暂停令牌，不取消 context、不建立取消令牌。继续接收进度和日志，仍占用并发名额，直到子进程结束。
- 仅在退出 75、最后一个结构化事件为 `type=result`、报告状态为 `paused` 且检查点路径、已完成文件数与无发布入口检查通过时，才进入 `paused`。报告保存到任务，`resumeRequired=true`。如果请求赶上正常完成，仍按原成功合同验证后进入 `succeeded`。
- 运行过的暂停任务继续时使用原 Spec、原检查点和新的取消令牌，移除旧暂停令牌，传 `--resume`；不重新调用要求空输出的提交参数校验，复用检查点的输入内容身份及参数一致性由 native 严格验证。
- 暂停请求对 `pausing / paused` 幂等；继续仅接受 `paused`。不合法状态返回 409，未知任务返回 404。任务管理器关闭后不接受暂停/继续。
- `cancel` 对 `queued / running / pausing / paused` 生效；有进程时真正取消 context，取消优先于任何迟到的暂停/成功结果；无进程时直接进入 `canceled`，不得继续。对于已确认暂停或续转排队中的任务，先核对检查点归属并持久化取消，再清理任务私有检查点和控制目录；保存失败保留原暂停状态及数据，清理失败显式记录并返回。暂停不伪装取消。

## 路径与持久化

用户创建请求仍只接受现有 `jobs.Spec`，不能指定检查点、暂停令牌或 resume。执行控制独立于用户 Spec。

任务管理器分配 `<dataDir>/checkpoints/<jobID>` 和 `<dataDir>/controls/<jobID>/pause`。检查点与暂停令牌分开，避免向 native 的检查点目录混入控制文件。检查点路径、`resumeRequired`、最近暂停时间、暂停结果和任务历史持久化到任务索引，日志沿用原单调递增 seq。排队暂停不需要检查点。无持久化目录的嵌入式管理器使用独立临时工作目录，关闭时清理；正式 App 始终提供 dataDir。

重启保留已经确认的 `paused` 任务及日志，队列不自动恢复；原 `queued / running / pausing` 仍标记中断失败，不能把未确认的暂停请求当成有效检查点。恢复时核对检查点仍归本任务拥有，拒绝索引中指向其他目录的路径。已暂停任务更换为不支持暂停能力的转换器时保留历史，但不允许继续。

暂停为可继续状态，`finishedAt` 只用于最终结束；`pausedAt` 记录最近一次暂停时间。首次 `startedAt` 保留，继续时清除上一轮退出码、报告及错误；暂停期间界面的耗时冻结在 pausedAt。每次暂停、继续及最终状态写入可增量查询的日志。

## 子进程与界面

支持能力时，从首次实际转换即传 `--checkpoint-dir PATH --pause-file PATH`；只有已确认的运行暂停再继续才传 `--resume`。旧转换器不接收新 flags。`Result.Paused` 明确传给任务管理器。退出码与状态必须对应，缺失/损坏/未知事件或非最终 result 均不能视为成功或暂停。

普通成功保留退出 0、完整报告 `complete`、编码/线程/内存预算/纹理策略一致、`tileset.json` 存在的严格校验，SRS/origin 等原参数传递不变。暂停报告独立校验共同合同规定的 `checkpointDir` 与非负 `filesCompleted`；不要求暂停报告伪造完整成功报告。

HTTP 新增 `POST /api/jobs/{id}/pause` 与 `/resume`，成功返回 202 和当前任务快照。SSE 保留现有事件类型，暂停后连接继续可观察后续继续操作。任务列表和详情沿用现有深色表格、按钮、焦点样式，仅新增“暂停”“继续”、正在暂停/已暂停状态和必要说明；异步操作禁用按钮，颜色之外保留文字状态。

## 验证与整合边界

- 用真实子进程 stub 读取真实 flags、处理暂停/取消令牌、写入检查点与结构化结果；用通道和 HTTP 边界门闩同步，不依赖 sleep 猜测进程进度。
- 验证运行暂停与取消区别、暂停继续 flags/参数与日志、并发名额、排队暂停无检查点/无 resume、重启保留暂停且不执行、能力缺失、错误退出/报告/检查点、已有非空输出保护、SSE/API 状态。
- 运行相关 Go 测试和 race 检查、Web 语法与必要交互检查。若本机 Go 工具链不满足 go.mod，应如实说明并用独立临时 modfile 进行本地验证，不改项目版本合同。
- 整合后必须使用真实 native 验证文件处理途中暂停且无发布入口、恢复后与完整转换资产一致、输入/有效参数改变拒绝复用、损坏检查点失败、重启和取消；stub 测试通过仅代表 App 协议与调度验证通过。
